# Agent Memory Management（Agent 记忆管理办法）

> 🌐 [English README](README.en.md)

一套**实践验证过**的多层 Agent 记忆管理方案。源自真实生产环境长期使用（Hermes Agent），提炼为与具体框架解耦的可复制协议。

**核心理念：记忆不是一块缓存，而是三层分工的体系。**

```
┌─────────────────────────────────────────────────┐
│  L1 缓存记忆  Cache Memory（注入层·每轮都在）      │
│  MEMORY.md（Agent 笔记）+ USER.md（用户档案）      │
│  上限可控（字符/令牌预算），标签化，随会话注入       │
├─────────────────────────────────────────────────┤
│  L2 存储记忆  Storage Memory（索引层·按需读取）     │
│  memory-kb/ 双卡结构（主题索引卡 + session 简介卡）    │
│  总目录自动维护，watchdog 双向同步，无限大可扩容       │
│  轻量起步：单文件 MEMORY-KB.md 也可（见 docs/03）     │
├─────────────────────────────────────────────────┤
│  L3 会话记录  Session（流水层·事后可查）            │
│  对话原文 + 工具调用，可搜索，周期归档              │
└─────────────────────────────────────────────────┘
```

---

## 为什么分三层

| 层 | 回答的问题 | 不这样做的代价 |
|---|---|---|
| L1 缓存记忆 | 每一轮对话，Agent 必须记得什么？ | 把什么都塞进来 → 上下文爆炸、每轮烧 token |
| L2 存储记忆 | 某个主题的完整细节放哪？跨会话怎么找？ | 只有缓存 → 细节挤爆预算；只有会话 → 搜不到 |
| L3 会话记录 | 当时到底发生了什么？怎么复盘？ | 只有索引没有原文 → 细节失真、无法溯源 |

**一句话原则：能放 L3 的不放 L1；L1 只放"每轮必须知道"的硬规则；L2 放"需要时能找到"的完整知识。**

## 快速上手（30 分钟接入）

1. **建目录结构**（见 `templates/` 与 `docs/03-存储记忆协议.md`）
2. **初始化 L1**：写 MEMORY.md（Agent 笔记）+ USER.md（用户档案），条目带标签、`§` 分隔
3. **初始化 L2**：建 memory-kb/ 与总目录.md，首个主题索引卡（**轻量起步**：也可先只用单个 MEMORY-KB.md 文件，容量大了再升级为目录）
4. **接入 Agent**：在系统提示注入 L1 两个文件；声明"归档/存储记忆"两个触发指令
5. **接入同步**（可选）：部署 md↔xlsx watchdog，让人类用 Excel 管理 L2

## 相关概念速查

- **触发词**：`归档` = 整理当前会话并收尾（L3→归档库 + session 简介卡进 L2 + 继承清单），执行完当前对话结束；`存储记忆` = 更新 L2 索引。两者勿混。
- **记忆审查**：后台自动写入可关闭；重大写入先人工确认；定期全文扫标签裁决。
- **跨 Agent**：文件格式是纯 Markdown + 标签约定，任何 LLM 都能读；同步脚本可复用。
