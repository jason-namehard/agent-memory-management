# 07 真实案例：从 5000+ 轮对话中提炼三层记忆

> 本案例来自本方案的原生环境（Hermes Agent）。**路径与模型名已泛化**；它说明的是"这套方案在真实高压场景下怎么跑、踩过什么坑"，不是教程。

## 7.1 背景

一个私人助理 Agent 连续工作 7 天，累积 **5000+ 轮对话**，覆盖：多 Agent 协作、环境排障、协议设计、跨 session 长任务。早期阶段"什么记忆都往缓存里塞"，出现两个典型症状：

- **上下文膨胀**：缓存记忆每轮注入，塞满 8000 字符后仍不够用 → 每轮烧 token，且重要规则被挤掉。
- **遗忘断层**：会话一长，早期拍板的决策（"主模型不要换"、"识图只用 X 模型"）被后续对话淹没 → 用户反复纠正。

## 7.2 三层落地过程

| 层 | 落地方案 | 实际形态 |
|---|---|---|
| L1 缓存 | MEMORY.md（Agent 笔记）+ USER.md（用户档案），每轮注入系统提示，带标签、`§` 分隔 | 从 13 条杂乱条目 → 压缩为"标签化 + 指针化"的高密度条目 |
| L2 存储 | 主题索引卡 + session 简介卡 | **轻量起步**：先单文件 MEMORY-KB.md 按主题分区，容量上来后升级目录 |
| L3 会话 | 周期归档：归档总结 → session 简介卡；继承清单 → 新 session | 每周归档一次，5 天周期提醒（周三/周日 cron） |

**关键动作（L1 瘦身）**：
1. 逐条打标签（`[环境]` `[工具坑]` `[偏好]` `[决策]` `[规则]` `[标签]`），让用户能扫读裁决。
2. 长知识外置：如"某远程管理主题"完整能力矩阵 500+ 字 → L2 索引卡，L1 只留一行指针。
3. 三条重复的"列其余方案"偏好 → 合并为一条（省 1/3 空间）。
4. 后台自动记忆写入关闭（`nudge_interval=0`），杜绝"悄悄写入错误教训"。

## 7.3 踩过的坑（方案演进依据）

- **"后台自动评审"只关通知不关写入** → 无效，必须从配置层关闭写入通道。
- **归档后继续对话** → 无限循环（归档→对话→再归档）。解法：归档是终局操作，执行完当前对话即止。
- **缓存记忆超限写入被拒** → 需要"一次调用内先删后加"的原子操作批量腾空间，而不是一条条试。
- **只靠会话记录找不到细节** → 必须建"主题索引卡"跨 session 聚合，靠 `[标签] → 指针` 触发读取。

## 7.4 收益（量化）

- L1 稳定在预算内（8000/3000 字符），每轮注入成本可控；
- 跨 session 继承零返工：新 session 开场读继承清单即可续接，无需重新摸索；
- 用户纠正次数显著下降（决策类条目写入前先确认，拍板后不再反复）。

## 7.5 可复刻要点

- 本案例的**所有过程产物**（模板、协议、脚本）就是本仓库内容——复制仓库即可复刻。
- 真实知识（你的 MEMORY.md / memory-kb/）不进仓库；用 `templates/` 起步，按 docs/02~06 的协议维护。
