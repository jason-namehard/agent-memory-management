# 01 三层架构：职责、边界、流转规则

## 1.1 分层总览

| 层 | 名称 | 载体 | 生命周期 | 访问方式 | 成本 |
|---|---|---|---|---|---|
| L1 | 缓存记忆 | MEMORY.md / USER.md | 随会话常驻 | **每轮注入**系统提示 | 高（每轮都付） |
| L2 | 存储记忆 | memory-kb/*.md + *.xlsx | 长期（无限大） | 按需读取（Agent 决定） | 低（读才付） |
| L3 | 会话记录 | state.db（消息流水） | 直到归档 | 事后搜索/复盘 | 零（不注入） |

**L2 是缓存记忆的扩容弹夹**：L1 有字符预算、L2 无上限。凡是"知道它存在才需要读"的内容都下放到 L2，L1 只留指针。

## 1.2 三层各自的"不可替代性"

- **L1 不可替代 L2**：L1 有字符上限，塞不下主题细节（如"某远程管理协议的能力矩阵"）；且 L1 每轮注入，放太多 = 每轮烧 token。
- **L2 不可替代 L1**：L2 是"按需读取"，如果 Agent 不知道某个主题存在，就不会去读——L1 必须放**触发指针**（"涉及 X 先读 memory-kb/x.md"）。
- **L3 不可替代 L2**：L2 是压缩后的索引（简介式概述），细节在原文里；出问题要查"当时到底怎么操作的"，只能回 L3。
- **L1/L2 不可替代 L3**：索引和缓存都会更新/压缩，原文是唯一事实源。

## 1.3 信息流转规则（核心）

```
【写入方向】
用户偏好/跨会话规则 ──► L1 缓存记忆（先确认，再写入）
主题完整知识        ──► L2 存储记忆（索引卡 + 总目录）
对话过程本身        ──► L3 会话记录（自动，无需操作）

【读取方向】
每轮开始 ──► 注入 L1（Agent 必读）
任务涉及某主题 ──► L1 里的标签指针 ──► 读 L2 索引卡 ──► 必要时回 L3 查原文
判定是否读某 session 正文 ──► 读 L2 的 session 简介卡（简介判定 → 值不值得读）

【归档方向】（周期触发，终局操作）
L3 会话记录 ──► 整理裁决 ──► 归档总结（→ session 简介卡进 L2）+ 继承清单（→ 新 session）
                │
                └─ 归档执行完 = 当前对话结束（防"归档→对话→再归档"循环）
```

## 1.4 三条铁律

1. **归档 ≠ 存储记忆**：归档整理当前会话（L3）并收尾，存储记忆是更新索引（L2）。归档会**自动**把归档总结转 session 简介卡进 L2 + 缓存记忆加一行指针；其余**绝不**自动写 L1——需用户裁决。
2. **迁移 = 拷贝非剪切**：任何信息从 L3 提炼到 L2/L1，原文保留，只增不减。
3. **能放 L3 的不放 L1**：任务进度、完成日志、一次性修正 → L3；只有"跨会话必须记得的硬规则/偏好/环境事实"才值得进 L1。

## 1.5 预算分配（示例）

以 128K 上下文窗口为例：

| 占用 | 预算 | 说明 |
|---|---|---|
| L1 缓存记忆 | ~4K 字符 ≈ 4K token（3%） | 8000 字符 MEMORY + 3000 字符 USER |
| 每轮对话 | ~10 轮 × 10K token | 输入 + 输出 |
| 工具/上下文 | 其余 | 留足余量防压缩 |

**结论：L1 是唯一每轮付钱的层，必须小而精。定期清扫（见 06-标签体系）是 L1 的保养动作；L2 无限大，装不下的都往 L2 放。**
