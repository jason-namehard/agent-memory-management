# 03 存储记忆协议（L2）

## 3.1 是什么

**memory-kb/**（记忆知识库）：**双卡结构**索引目录。缓存记忆是"书名"，存储记忆是"目录"，会话记录是"正文"。

- L1 只放一句话指针（"涉及 X → memory-kb/x.md"）
- L2 存放该主题的**核心结论 + 详细内容位置 + session 定位**
- 需要细节时，Agent 按指针读取

**L2 是无限大的（无字符预算）**——缓存记忆的扩容弹夹。凡是"知道它存在才需要读"的内容，从 L1 下放到这里；L1 只留指针。

## 3.2 双卡结构（两类索引卡）

| 卡片类型 | 按什么组织 | 内容 | 来源 |
|---|---|---|---|
| **主题索引卡** | 按事件/主题 | 主题核心结论、能力矩阵、数据位置、session 定位 | "存储记忆"触发 / 归档时提炼 |
| **session 简介卡** | 按时间/session | 该 session 的简介式总结、主线、未完成任务、环境快照 | 归档时由归档总结转化 |

- **主题索引卡**回答："某个主题的完整细节在哪？"（跨 session 聚合，一对多）
- **session 简介卡**回答："这个 session 大概干了什么？值不值得读正文？"（读取 L3 原文前的简介判定）
- 两者互补：主题卡按能力找、session 卡按时间找；判定"是否有必要读某 session 正文"看 session 简介卡

## 3.3 目录结构

```markdown
memory-kb/
├── 总目录.md            # 自动生成的索引（勿手改）
├── 总目录.xlsx          # Excel 版（与 md 双向同步）
├── 主题A.md             # 主题索引卡
├── session-YYYYMMDD.md  # session 简介卡（归档时新增）
└── ...
```

> **两种应用形态（按容量选）**：
> - **轻量起步（单文件）**：只建一个 `MEMORY-KB.md`，主题用 `## 二级标题` 分区。适合早期（<50 条）或单机个人使用；缺点是并发冲突面大、无总目录自动维护。
> - **规范形态（目录）**：本协议描述的 memory-kb/ 双卡目录。适合多主题积累、多 Agent 共享；配合 `memorykb_sync.py` 自动维护总目录与 Excel 视图。
> 单文件可随时升级为目录（按主题拆分即可，迁移=拷贝非剪切）。

## 3.4 主题索引卡格式（templates/索引卡.template.md）

```markdown
# 主题名 — 索引卡

> 标签：分类/子类/主题名
> MEMORY.md 只存标签「主题→本文件」。本文件是索引卡：核心结论 + 详细内容位置。
> 涉及该主题任务时，先读本文件，再按需读 skill/原文。

## 核心结论（一句话）
[压缩后的结论，未来会话直接可用]

## 能力矩阵/要点表（可选）
| 能力 | 状态 | 说明 |
|---|---|---|

## 数据位置
[文件/库/端点路径]

## 详细内容位置
- skill `xxx`（SKILL.md + references/）
- session 定位（哪个 session 哪部分）
```

**一对多规则**：一项任务可索引多个 session（跨 session 变体）；需要时翻遍全部相关 session，不假设只有一处。

## 3.5 session 简介卡格式（templates/session简介卡.template.md）

```markdown
# Session 简介卡 — YYYY-MM-DD ~ YYYY-MM-DD

> 来源 session：{session_id}（{消息数} 条，{天数} 天）
> 归档日期：{日期}。本卡 = 归档总结的存储记忆形态。

## 主线（本 session 做了什么）
### 1. {主题}
- 要点…

## 未完成任务（→ 继承清单）
| # | 任务 | 说明 |
|---|---|---|

## 关键环境状态（继承快照）
- {环境事实}
```

**与缓存记忆的链接**：归档后，缓存记忆（MEMORY.md）新增一行指针——
`[归档] {日期} session → memory-kb/session-{YYYYMMDD}.md + 归档目录（原文）`
缓存记忆只存指针，简介全文在存储记忆。

## 3.6 总目录（自动维护）

| 文件名 | 一级 | 二级 | 三级 | 一句话摘要 | 修改日期 |

- 由 `memorykb_sync.py index` 自动生成，**勿手改**
- 每次索引卡变更后重跑，保持目录最新
- session 简介卡同样进总目录，一级=时间类、二级=会话

## 3.7 Excel 双向同步（人类管理入口）

**动机**：用户（尤其非程序员）用 Excel 管理 md 比直接编辑 markdown 顺手。watchdog 实现：

- **md → xlsx**：md 变更后自动同步到对应 xlsx（表格化呈现）
- **xlsx → md**：用户在 Excel 修改后自动反写 md
- 双向：`memorykb_sync.py watch` 常驻监听文件变化

**运行方式**：
- 手动：`python memorykb_sync.py watch`
- 开机自启：注册表 Run 项（可选，取决于用户是否要常驻）

## 3.8 触发词与操作

| 用户说 | 动作 |
|---|---|
| "存储记忆" | 建立/更新索引：先查相似同名 → 优先合并 → 用户裁决 → 写索引卡 + 更新总目录 |
| "归档" | 整理当前会话 → 归档总结转化为 **session 简介卡** 写入 memory-kb（+ 缓存记忆指针），详见 04 协议 |
| （无触发） | 不自动建索引，绝不自动写缓存记忆 |

**写入流程**：
1. 查 memory-kb 是否有相似同名主题（先查相似同名）
2. 有 → 列出新旧给用户裁决合并
3. 无 → 新建索引卡（模板）
4. 更新总目录

## 3.9 什么进 L2（与 L1 的边界）

| 进 L2 | 不进 L2 |
|---|---|
| 主题完整知识、能力矩阵、协议细节 | 每轮必需的硬规则（那是 L1） |
| 工具/脚本位置、API 端点 | 任务进度 |
| 高价值任务的简介式概述 | 一次性对话内容（那是 L3） |
| session 定位（哪个 session 哪部分） | — |
| session 简介（简介卡） | — |

**判断标准**：内容需要"知道它存在才去读"→ L2；内容"不知道存在就会出错"→ L1。
