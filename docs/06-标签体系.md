# 06 标签体系与记忆裁决

## 6.1 为什么用标签

L1 缓存记忆是条目集合。没有标签时，用户无法快速判断"这条为什么在这、该不该留"。标签让**人可扫读、机器可分类**，是记忆审查（裁决留/删/改）的前提。

## 6.2 标签分类法（MEMORY.md 用）

| 标签 | 含义 | 示例 |
|---|---|---|
| `[环境]` | 机器/路径/配置事实 | 工作目录 {路径} |
| `[工具坑]` | 踩过的坑 + 规避方法 | .bat 必须纯 ASCII |
| `[偏好]` | 用户规则（最高优先级） | 回复要简洁可执行 |
| `[决策]` | 已拍板决定（用户定夺） | 主模型用 {模型名} |
| `[项目]` | 历史项目引用 | 项目 X → memory-kb/x.md |
| `[规则]` | 行为规则（跨会话） | 归档≠存储记忆 |
| `[标签]` | 指向 L2 的触发指针 | {主题}→memory-kb/{主题}.md |

**USER.md 约定**：保持无标签（用户档案，人工维护，不参与机器裁决）。

## 6.3 裁决流程（记忆审查）

**触发方式**：
- 用户说"确认今天的记忆" → 列**当天新增**待裁决条目
- 每周日自动整理 → 列**全文**扫标签裁决

**呈现格式**（带序号，用户输序号管理）：

```
MEMORY.md 当前 12 条 / 8000 字符
1. [环境] 工作目录…        （8/1 新增）
2. [工具坑] .bat 编码…      （8/3 新增）
...
请裁决：留 / 删第X条 / 改第X条为…
```

**用户可下达的指令**：
- `留` — 保持不动
- `删第X条` — 删除该条
- `改第X条为…` — 替换内容

## 6.4 压缩技巧（接近上限时）

1. **合并重复**：多条表达同一偏好的 → 合并为一条（真实案例：三条"列其余方案"偏好 → 一条）
2. **删过期**：已解决的坑、已推翻的决策 → 删除
3. **压缩描述**：冗长环境说明 → 精简为要点（保留关键路径/命令，删背景故事）
4. **原子操作**：一次调用内 先删后加（合并腾出的空间立即装下新条目）

## 6.5 防错机制

- **后台自动评审默认关闭**：`nudge_interval=0`（memory + skills 双通道），禁止悄悄写入
- **重大写入先确认**：偏好/跨会话规则文本先给用户过目
- **收口随时做**：清理/合并不需要批准，随时可做
- **只执行不弹窗**：记忆操作执行但不汇报（用户嫌吵），除非用户要求

## 6.6 质量判断标准

一条好的 L1 条目：
- [ ] 一句话自包含（未来无上下文也能读懂）
- [ ] 带标签可分类
- [ ] 一周后仍然重要（不会过期）
- [ ] 是事实/规则/决策，不是任务进度
- [ ] 指向 L2 的用"→"指针，不内嵌细节
