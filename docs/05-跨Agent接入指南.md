# 05 跨 Agent 接入指南

本方案的 L1/L2 是**纯文件 + 约定**，不绑定任何 Agent 框架。任何 LLM 应用（Claude Code、Codex、OpenCode、自研 Agent、多 Agent 协作）都能接入。本指南回答："换一个 Agent/模型，记忆怎么迁移、怎么继续管？"

## 5.1 接入契约（最小集）

接入新 Agent 只需要满足三条契约：

| 契约 | 内容 | 本方案的实现 |
|---|---|---|
| 1. 注入契约 | 每轮对话开始，把 L1 两个文件注入上下文 | 系统提示注入 MEMORY.md + USER.md |
| 2. 读取契约 | Agent 能按指针读取 L2 索引卡 | 文件系统：memory-kb/*.md |
| 3. 写入契约 | Agent 能按规则写 L1/L2 | memory 工具 / 文件写入 |

**任何能读文件、能写文件的 LLM Agent 都能接入。**

## 5.2 接入步骤

1. **复制目录**：把 memory-kb/ 整个拷到新 Agent 的工作区（迁移=拷贝非剪切，原处保留）
2. **注入 L1**：在新 Agent 的系统提示里追加：
   ```
   以下是你的持久记忆，每轮必读：
   [粘贴 MEMORY.md]
   [粘贴 USER.md]
   写入规则：重大变更先经用户确认；后台不得自动写入。
   ```
3. **声明触发词**：告知新 Agent "归档"和"存储记忆"两个指令的含义（见 docs/04）
4. **标签指针**：确认 MEMORY.md 里的标签能触发新 Agent 读取对应索引卡
5. **测试**：让新 Agent 复述一条 L1 规则 + 按指针读一张 L2 索引卡

## 5.3 多 Agent 场景（一个记忆库，多个执行者）

```
                 ┌── Agent A（主力 Agent）
L1/L2 记忆库 ────┤
（共享文件）       ├── Agent B（桌面实操 Agent）
                 └── Agent C（代码/审计 Agent）
```

- **共享**：L1/L2 是文件，所有 Agent 读同一份 → 认知一致
- **分工**：每个 Agent 可注入同一份 L1，但各自按职责读不同 L2 索引卡
- **冲突风险**：并发写 L1 → 用锁文件（.lock）或"写前确认"流程；L2 各主题索引卡天然分片，冲突少
- **权限分层**：核心 Agent 可写 L1/L2；辅助 Agent 只读或经核心 Agent 中转写（避免错误教训入库）

## 5.4 模型无关性说明

- L1 格式（Markdown + 标签 + § 分隔）是任何 LLM 都能解析的纯文本，无框架语法
- L2 索引卡是普通 md 表格，无特殊格式
- 标签体系是人类可读的分类法，不依赖模型能力
- 归档流程是操作流程，与模型无关

**唯一模型相关的**：L1 的字符预算应随模型上下文窗口调整（128K 窗口配 11K 字符 L1；32K 窗口建议 ≤4K 字符）。

## 5.5 迁移场景速查

| 场景 | 做法 |
|---|---|
| 换主模型（同框架） | 无感：L1/L2 不变，只换模型配置 |
| 换框架（如 Hermes→自研） | 拷 memory-kb/ + L1 文件，重配注入与触发词 |
| 加辅助 Agent | 共享 L1，只读 L2，写需经核心中转 |
| 团队/多人 | L2 是天然共享库；L1 按人分文件（USER.md 每用户一份） |

## 5.6 接入检查表

- [ ] L1 注入生效（新 Agent 能复述规则）
- [ ] L2 读取生效（按指针读到索引卡）
- [ ] 写入规则生效（重大变更先确认）
- [ ] 触发词声明（归档/存储记忆）
- [ ] 锁/并发策略就位（多 Agent 场景）
