# 02 缓存记忆协议（L1）

## 2.1 是什么

两个纯 Markdown 文件，每个会话开始时注入系统提示，Agent 每轮都能读到：

- **MEMORY.md** — Agent 自己的笔记：环境事实、工具坑、决策、规则、项目指针
- **USER.md** — 用户档案：身份、偏好、工作习惯、协作约定

## 2.2 格式约定

```
[标签] 内容（含日期/出处，一句话说清）

[标签] 另一条内容
§
```

- 每条以 `[标签]` 开头（见 docs/06-标签体系.md）
- 条目之间以 `§` 分隔（独立行）
- 每条**自包含**：未来会话没有本条上下文，必须一句话读懂
- 可含"→"指针：`[标签] X相关→memory-kb/x.md`（触发 L2 读取）

## 2.3 字符预算

| 文件 | 建议上限 | 依据 |
|---|---|---|
| MEMORY.md | 8000 字符 | Agent 笔记，硬规则/环境/决策 |
| USER.md | 3000 字符 | 用户档案，偏好与习惯 |

**为什么设上限**：L1 每轮注入 = 每轮付 token。超限内容压缩后仍占窗口，且挤占对话空间。
**超限处理**：写入被拒 → 单次操作批量合并/删除旧条目腾空间（原子操作：一次调用内先删后加）。

## 2.4 写入规则（谁有权限写）

1. **重大写入先确认**：偏好、跨会话规则 → 先把文本给用户过目，批准后才写。
2. **收口/清理随时做**：合并重复、删过期条目，无需批准。
3. **后台自动评审默认关闭**：禁止"无人值守的悄悄写入"——这是错误教训入库的主要通道。
   - 关闭命令示例：`nudge_interval=0`（memory 与 skills 两个通道都关）
   - 只关通知不关写入是无效的：通知只是 UI，写入照旧。

## 2.5 什么不该进 L1（反模式）

| 不该进 | 该去哪 |
|---|---|
| 任务进度、完成日志 | L3 会话记录 |
| PR 号、commit SHA、一次性问题 | L3 会话记录 |
| 主题完整细节 | L2 存储记忆（L1 只放指针） |
| 临时 TODO | L3 或任务列表 |
| 每轮都变的状态 | 任何层都不该进 |

**判断标准**：一周后这条还重要吗？会过期的 → 别进 L1。

## 2.6 维护节奏

- **每日**：用户说"确认今天的记忆" → 列当天新增待裁决条目
- **每周**：列全文扫标签，逐条裁决 留/删/改（自动化：weekly_memory_review.sh）
- **随时**：合并重复条目、压缩冗长描述、删除已解决的工具坑

- [ ] 每条带标签、`§` 分隔、自包含
