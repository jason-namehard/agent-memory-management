# 04 会话与归档协议（L3）

## 4.1 是什么

**L3 会话记录**：对话流水账（原文 + 工具调用），自动存储、可搜索（全文检索）。是三层中的"事实源"——L2 索引可能过期、L1 可能被压缩，但 L3 原文永久可查。

## 4.2 生命周期

```
开始 ──► 进行（自动记录）──► 归档点（触发）──► 开新会话（自动读继承清单）
                ▲                                        │
                └──────────────── 新会话续接 ◄───────────┘
```

- 归档点是**主动动作**，不是自动的：到周期（如每周）提醒用户"该归档开新会话了"
- 归档解决的核心问题：会话太长 → 上下文膨胀 → 每轮烧 token → 记忆混乱

## 4.3 归档流程（新规则·六步）

> 用户说"归档"时执行。**归档是终局操作：执行完毕当前对话直接结束，归档记忆截止至最后一条消息。**

1. **列出本会话内容清单**：带序号列出本 session 做过的事（小标题/主题分组，不是逐条消息）
2. **用户裁决**：用户输序号指定每项的处置——继承 / 删除 / 压缩
3. **整理归档**：按裁决整理归档内容
4. **撰写两份文档**：
   - **归档总结** → 转化为 **session 简介卡** 写入存储记忆（memory-kb/），缓存记忆加一行指针（见 4.5）
   - **新session继承任务清单** → 供新 session 读取（唯一交接文档）
5. **直接开新 session**：旧会话归档，新会话开始，**自动读取继承清单**
6. **当前对话结束**：不再继续对话（避免"归档完又对话→又要重新归档"的无限循环）

**为什么归档后不再对话**：归档后若继续对话，旧 session 又新增消息 → 需重新归档 → 归档后又有新消息 → 无限循环。归档截止点 = 执行归档的消息。

## 4.4 归档库结构

```
归档/
├── YYYY-MM-DD-session归档/
│   ├── 归档总结.md          # 本会话完整总结（session 简介卡的原始素材，同步进存储记忆）
│   └── 新session继承任务清单.md  # 新 session 唯一交接文档（必读）
└── ...
```

> 归档目录自带日期文件夹，天然按时间检索，无需额外索引文件。跨 session 检索靠存储记忆（总目录 + session 简介卡）。

## 4.5 归档总结 → session 简介卡（落存储记忆）

归档总结**不是**给新 session 读的（新 session 只读继承清单），而是写给**存储记忆**的：

- 归档时：归档总结.md 完成 → 同步转化一份 **session 简介卡** 存入 `memory-kb/session-YYYYMMDD.md`（格式见 03 协议 3.5）
- 缓存记忆（MEMORY.md）只加一行指针：`[归档] {日期} session → memory-kb/session-{YYYYMMDD}.md`
- 用途：读取 L3 原文正文前的**简介判定**——"这个 session 大概干了什么？值不值得读？"
- 存储记忆是无限大的（缓存记忆的扩容弹夹），session 简介卡不占 L1 预算

## 4.6 归档 vs 存储记忆（关键区分）

| | 归档 | 存储记忆 |
|---|---|---|
| 对象 | 当前会话（L3） | 知识库索引（L2） |
| 触发 | "归档" | "存储记忆" |
| 动作 | 整理总结 → 归档总结 + 继承清单 → 开新 session | 建/更新索引卡 + 总目录 |
| 写 L1？ | 仅一行 session 指针（自动） | 经用户裁决才写 |
| 写 L2？ | 归档总结转 session 简介卡（是） | 是（本体） |

**一句话：归档收尾一个会话（终局），产物中的简介进存储记忆，交接文档给新 session。**

## 4.7 继承文档（开新会话前必做）

归档时产出**继承清单**（templates/继承清单.template 可参考），包含：

- 本会话**未完成**的任务清单（每项：目标、现状、下一步、相关文件/session 定位）
- 需要延续的约定与上下文
- 新会话开场动作：**读取继承清单 → 汇报工作计划**

新 session 的 Agent 不用重新摸索，直接续接。

## 4.8 常见问题

- **Q：会话太长必须归档吗？** 有压缩机制可临时续命，但压缩会丢细节；归档是根本解法。建议：每周或每 500 轮左右归档一次。
- **Q：归档会丢记忆吗？** 不会。L3 原文留档可查；简介进 L2 存储记忆；交接文档给新 session。丢的只是"当前会话的上下文窗口"，这正是目的。
- **Q：归档后为什么不能继续对话？** 防止"归档→对话→再归档"无限循环。归档执行完即止，新任务到新 session 说。
- **Q：归档总结给谁看？** 存储记忆（session 简介卡）+ 人工回溯。新 session 不读它，只读继承清单。
- **Q：窗口还能看到旧对话？** 前端 UI 显示的是已渲染画面（显示层），归档清的是数据库记录（记忆层）。已显示内容不会消失，但记录层已无。
